# SANMON:04 — 小4算数 まるごと学習ゲーム

小学4年生の算数**全14単元**(学習指導要領・東京書籍『新編 新しい算数 4上・4下』準拠)を、
ゲームを通して網羅的に学習できるWebアプリです。

**収録単元**: 大きい数のしくみ / 折れ線グラフと表 / わり算の筆算(÷1けた・÷2けた) / 角の大きさ /
小数のしくみ / がい数 / 計算のきまり / 面積 / 小数のかけ算とわり算 / 分数 / 変わり方調べ /
直方体と立方体(位置の表し方) / 倍の見方 — **14ワールド・151サブトピック・3,341問**。
わり算筆算・がい数・小数・倍の見方は参照リポジトリ
(wari-hissann3 / syo4-gaisu / syo4-syousu / syo4-bainomikata)の問題項目を移植しています。

設計はエビデンスに基づいています(数直線を中心的表現とする WWC 分数実践ガイド、精緻化フィードバック、
誤答例からの学習、足場のフェーディング等)。詳細な設計根拠・エビデンスレベル・例題は **[docs/DESIGN.md](docs/DESIGN.md)**、
ぼうけんモードの設計は **[docs/ADVENTURE.md](docs/ADVENTURE.md)**、
ゲーム要素の追加検討とエビデンス評定は **[docs/GAME_ELEMENTS_PROPOSAL.md](docs/GAME_ELEMENTS_PROPOSAL.md)** を参照してください。

| 📝 本番テスト | 新学社まとめテスト形式の**8セット**(大きい数/グラフと表/わり算の筆算/がい数/小数/分数/1学期まとめ/前期まとめ)。表=知識・技能100点/裏=思考・判断・表現50点、大問別の得点と全設問の詳細を記録 |
| 📒 がくしゅうのきろく | きょうやった問題の即時確認・デイリー目標リング・サブトピック別習熟バー・バッジ・テスト履歴 |

### 🗺 ぼうけんモード「ナンバーランド」

**151のサブトピック = 151体のモンスター**。図鑑を埋めることが、そのまま小4算数を
ひととおり解くことになるよう設計している。

- **フィールド**: react-three-fiber の3D空間(地形・草むら・水面・霧・時間帯ライティング)を
  歩く。キャラクターは2Dスプライトのビルボード ―― ポケモンのDS/3DS作品と同じ方式で、
  手描きの絵をそのまま3D空間に立てている
- **バトル**: モンスターの攻撃 = 算数の問題。正解でこちらの攻撃が当たり、まちがえると
  ダメージ。**まちがえたらヒントが出て、もう一度だけ挑戦できる**(直せたらダメージは半分入る)。
  まちがえた問題は自動で復習モード(SRS)に登録される
- **タイプ相性**: かず ▶ けいさん ▶ しょうすう ▶ ぶんすう ▶ ばい ▶ グラフ ▶ ずけい ▶ かず…
  の7すくみ。覚えることは輪の順番ひとつだけ
- **ゲット**: 弱らせて「サンスウボール」を投げる。手持ちは3体まで
- **ジム(単元マスター)**: 各町の道場にいる。いきなりは挑めず、**その町のトレーナーに勝つ /
  その単元のモンスターをつかまえる / その単元の問題に正解する**の3条件を満たすと受けてくれる。
  正解数は練習モードでの学習も算入される
- **ステータス・称号**: トレーナーカードに進行状況を集計。称号27種・トレーナーランク10段階
- **進化**: 151項目のうち、学習上とくに重要な**44項目**だけに進化がある。
  レベルではなく「その項目を5問れんぞくで正解できるようになったとき」に姿が変わる
- **伝説・幻**: 伝説7体(タイプごとに1体)と幻2体。町の**祠**で伝承が読め、
  その単元をやりこむと出現する。1体ずつしかいない
- **テキトウ団**: 「およそでいい」と算数の"だいたい"を悪用する集団。
  バッジの数に応じて5つの章が進み、最後はアジトでボス戦
- **進行**: 14の町はどこから回ってもよい。ただし先生が管理画面でロックした単元の町には入れない。
  14個のバッジがそろうと**ナンバーリーグ**が開く ―― 専用の3D回廊を奥へ歩き、
  四天王を1人ずつ倒すたびに扉が開き、いちばん奥にチャンピオンがいる
- **操作**: 左下のバーチャルパッド + 画面タップ移動の両対応(iPad横持ち想定)

## ごほうびシステム

- **バッジ**(ワールドクリア🚩×14・単元マスター👑×14・正解数・連続正解・ログイン・テスト得点/満点回数)

### Firebase(オンライン機能)の設定

Firebase未設定でも**オフラインモード(端末内保存)で全学習機能が動作**します。
ログイン・PvP・端末をまたぐ記録同期・先生向け機能を使う場合のみ設定してください。

1. [Firebase Console](https://console.firebase.google.com/) で新しいプロジェクトを作成
2. **Authentication** → ログイン方法で「Google」を有効化
3. **Firestore Database** → データベースを作成(本番モード)
4. プロジェクトの設定 → ウェブアプリを追加 → 表示された設定値を `.env.example` を参考に `.env.local` へ記入
5. `firestore.rules` をコンソールのルールにコピー、`firestore.indexes.json` のインデックスを作成

```bash
cp .env.example .env.local
# VITE_FIREBASE_* を記入
```

学校名は `VITE_SCHOOL_NAME` で設定します(ログインは自校のみの簡易方式: 組と出席番号を選ぶだけ)。

## 技術構成

- React 19 + TypeScript + Vite + Tailwind CSS
- **react-three-fiber / three.js**(ぼうけんモードの3Dフィールド。選んだときだけ読みこむ動的インポート)
- Zustand(進捗・ゲーミフィケーション状態・ぼうけんのセーブ)
- Firebase Authentication / Cloud Firestore(任意・環境変数で注入)
- 問題データは決定的に生成(乱数なし)— PvPで全クライアントのカード定義が一致
- わり算のあまりは「24あまり3」形式、大きい数は「180億」と「18000000000」の両表記を正答、小数は数値比較(1.60=1.6)で採点

## 開発メモ

- 採点は `utils/answerChecker.ts` に一本化。分数は `utils/fraction.ts` が
  「値+分母の両立」で判定(帯分数⇔仮分数の等値表現を許容、約分形は4年未習のため不可、
  変換問題は `requireForm` で解答形式を固定)
- 分数の表示は `components/FractionText.tsx`(積み上げ表記)。問題文は `{3/4}` `{2と1/3}` マークアップ
- 数直線・リットルます・テープ図は `utils/fractionSvg.ts` が決定的SVGとして生成
- `reference/` は参照専用資料(Git・ビルド対象外)
- ぼうけんモードのデータは `data/adventure/`(タイプ相性・モンスター・町・登場人物)、
  画面は `components/adventure/`、セーブは `store/adventureStore.ts`
- 問題の見た目は `components/ProblemQuestionView.tsx`、解答らんとキーパッドは
  `components/ProblemAnswerPad.tsx` に一本化。練習モードと3Dバトルが同じ
  コンポーネントを使うので、モードによって解答方法が変わることはない

## モンスターのイラスト生成

図鑑の151体+進化44体+伝説9体+ボス14体+主人公+NPC+地形テクスチャ(合計280枚)は、
**Pollinations.ai**(無料・APIキー不要)で生成し、
自作の背景除去パイプラインで透過PNG化している。

モンスターは**必ず目が2つ**になるようプロンプトで固定し(`EXACTLY TWO EYES and no more`)、
三つ目・複眼・左右非対称な目をネガティブプロンプトで除外している。

```bash
node scripts/build-sprite-manifest.mjs   # ゲームデータから生成ジョブ一覧を作る
node scripts/gen-sprites.mjs             # 生成(既存ファイルはスキップ)
node scripts/check-sprites.mjs --bad     # 抜け残り・抜きすぎ・複数キャラを機械的に検査
node scripts/contact-sheet.mjs           # 一覧シートを作って目視で確認する
node scripts/gen-sprites.mjs --force --only monsters/mon-055     # 1枚だけ作り直し
node scripts/gen-sprites.mjs --force --list scripts/redo.txt     # まとめて作り直し
```

- 画風は「フラットな2Dベクター/サンリオ風/大きな丸い目/グラデーション・毛並み・写実の排除」で統一。
  難易度が上がるほど `baby → brave → knight → dragon` と、かっこいい方向へ寄せている
- 背景は**必ずクロマグリーン**で生成させ、その色からの塗りつぶしで抜く。背景が緑でなければ
  生成し直す(白背景だと白い服・白い体のキャラが背景ごと溶けるため)
- 生成AIは指示を外すことがあるので、機械検査(緑の抜け残り・塗りつぶしすぎ・
  体に空いた穴・1枚に複数キャラ)で落ちたものだけ `scripts/redo.txt` に集めて作り直す。
  目の数など機械では判定できないものは、`contact-sheet.mjs` の一覧シートで目視確認する
- 生成物は `public/assets/adventure/` に入り、リポジトリにコミットしてある。
  再生成しなくてもそのまま動く

## 先生向け機能(管理画面)

- **単元ロック**: `config/unit_locks` にロックする単元名を保存。まだ学習していない単元のカード・練習・ショップ・スピードデュエルを児童側で使用不可にできる(読み1回/起動・書き1回/保存)
- **学習分析**: 児童側は端末内に日次集計し、セッション終了時に `dailySummaries/{uid_日付}` へ 1回の setDoc(merge) のみ。管理画面は選んだ日付の1クエリで、取り組み・正答率・誤答の多いサブトピック・児童別の単元内訳を表示(150人×毎日でも無料枠に収まる設計)
- **個別ランキングは児童側に表示しない**(比較による動機低下を避け、自分の進捗・バッジ・背景で動機づけ)
