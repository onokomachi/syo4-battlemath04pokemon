# 問題の品質管理 — 実際に出たバグと、その見つけ方

3,341問を人力のテストプレイで検品するのは現実的でない。
機械で見つかるものは機械で見つけ、人は「機械では判断できないもの」だけを見る。

```bash
node scripts/audit-problems.mjs
```

---

## 1. 実際に出たバグの型

### 型A: 答えが問題文にそのまま書いてある(テンプレートの設計ミス)

けん算の問題が、こういう文だった:

> **156** ÷ 12 = 13 あまり 0 の けん算の式を 書きましょう。

聞きたいのは「12 × 13 + 0 を計算するといくつか」なのに、
その答えである わられる数 156 を問題文に出してしまっていた。**20問が該当。**

→ わられる数を見せない文に書きかえた。
テンプレートで一括生成する問題は、1つ間違うと数十問が同時に壊れる。

### 型B: 数がたまたま一致してしまった(いちばん見つけにくい)

問題文の設計は正しいのに、選んだ数字のせいで答えが問題文の中に現れる。

| 問題 | 答え | 何が起きたか |
|---|---|---|
| 144本を12人で分ける | 12 | 144 ÷ 12 = 12。答えが「わる数」と同じ |
| 4/5 − 2/5 | 2/5 | 答えが「ひく数」と同じ |
| まわりの長さ16cmの正方形の面積 | 16 | 1辺4cmのときだけ周と面積が一致 |
| 132 ÷ (23 − 11) | 11 | 答えが式の中の数と同じ |

子どもは正しく解かなくても、問題文から数を拾えば当たってしまう。
**目視では絶対に見つからない。9問が該当し、すべて数を差しかえた。**

### 型C: 問題文の補助表記が答えを漏らしていた

「位」を答える問題で、数字の横に漢数字を添えていた:

> 79 2000 0000**(七億九千二百万)** の 2 は 何の位ですか。

答えである「千万の位」が、そのまま括弧に書いてある。
**練習問題の時点で間違っていた。**

→ 漢数字をやめ、4桁ずつ区切って表示する `groupedDigits()` に変えた。
**補助表記を足すときは、それが答えを含まないか必ず確認する。**

### 型D: ヒントが答えそのものだった

「ヒントを見る」を押すと答えが書いてあった。ヒントは
**考える道すじを示すもので、答えを言うものではない。**

→ 全ヒントを「どこに注目するか」の言い方に書きかえた。
あわせて、ヒントを見たら攻撃力が下がる仕組みを入れた
(ノーヒントで解くことに意味を持たせるため)。

### 型E: 答えが一つに定まらない

「この数字の 5 は何の位ですか」と聞いているのに、
その数の中に 5 が5〜10回出てくる問題があった。どの 5 のことか分からない。

→ 対象の数字がちょうど1回しか出てこない数に差しかえ、
さらに**生成時に `occurrences !== 1` なら例外を投げる**ガードを入れた。
同じ間違いが二度と混入しない。

## 2. 監査で出るが「直してはいけない」もの

素朴に「答えが問題文に含まれるか」を見ると **424件** 出るが、
そのほとんどは問題の形式上あたりまえのもの。数字の答えについて
「前後が数字でないときだけ」に絞りこんで **127件**まで減らし、
残りを目視で分類した結果、以下はすべて正常だった。

- **大小くらべ**「12と15では どちらが大きいですか」→ 答 15。両方書くのが当然
- **分類**「1/2, 5/3, 2 1/4 のうち 仮分数はどれ」→ 答 5/3。選択肢が文中にある
- **はい/いいえ**「〜といえますか」→ 答「いえる」
- **小数の位**「0.35 の小数第一位の数字は」→ 答 3。数字が文中にあるのは当然

**判断の基準**: 子どもが「問題文から数を拾うだけ」で正解できてしまうならバグ。
選択肢や比較対象として提示されているだけなら正常。

---

## 3. 問題を足すときの決めごと

1. コミット前に `node scripts/audit-problems.mjs` を流す
2. テンプレート生成の問題は、**生成結果を数問プリントして目で見る**
   (1つの誤りが数十問に広がるため)
3. 答えが「問題文中のどれかの数」と一致していないか確かめる(型B)
4. 問題文に補助表記を足すなら、それが答えを含まないか確かめる(型C)
5. ヒントは「注目点」を書く。答えは書かない(型D)
6. 「どれのことか」が一意に決まるか確かめる。決まらないならガードを入れる(型E)
