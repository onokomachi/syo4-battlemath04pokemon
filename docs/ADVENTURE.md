# ぼうけんモード「ナンバーランド」— 設計メモ

小4算数の全14単元・151サブトピックを、3Dフィールドを歩いて集める
モンスター図鑑として遊べるようにしたモード。

以下は「なぜそうしたか」の記録なので、あとから作りかえるときの判断材料に使ってほしい。

---

## 1. いちばん大事な決めごと

### 151サブトピック = 151体のモンスター

`constants.ts` の `MATH_CATEGORIES` を学習順に走査して図鑑番号を振っているだけなので、
**問題データを足せば図鑑も自動で増える**。モンスターの名前・見た目・説明は
`data/adventure/monsterRoster.ts` にサブトピック名をキーとして書いてある。
ロスターに無いサブトピックが現れても落ちず、自動生成の名前で埋まる。

これにより「図鑑を完成させる = 小4算数をひととおり解く」が構造的に成立する。
ゲームの目標と学習の目標が別々にならないようにするための、いちばん重要な設計。

### 学習まわりは1行も作り直していない

問題データ・採点(`utils/answerChecker.ts`)・ガイド付き解答UI(筆算シミュレーター等)・
間隔反復(SRS)・学習記録・弱点分析は、練習モードとまったく同じものを呼んでいる。

そのために `ProblemScreen.tsx` にインラインで書かれていた問題ビューを
`components/ProblemQuestionView.tsx` に切り出した。**練習モードと3Dバトルが
同じコンポーネントを使う**ので、「モードによって同じ問題の答え方が違う」ことが
起こらない。

## 2. タイプ相性は「7すくみ」だけ

```
かず ▶ けいさん ▶ しょうすう ▶ ぶんすう ▶ ばい ▶ グラフ ▶ ずけい ▶ (かずへ戻る)
```

矢印の向きが「こうかは ばつぐん(×2)」、逆向きが「いまひとつ(×0.5)」、
それ以外はすべて等倍。**覚えるのは輪の順番ひとつだけ**にしてある。

18タイプ×18タイプの表を小4に覚えさせるのは学習の妨げになるだけなので採らなかった。
14単元を7タイプにまとめた対応は `data/adventure/elements.ts` の `ELEMENTS[].units`。

相性を外しても勝てる(×0.5で終わり、無効はない)ようにしてあるので、
「相性を考えると気持ちいい」が「相性を外すと詰む」にはならない。

## 3. まちがえたときの設計

学習アプリとして、ここがいちばん時間をかけた部分。

| できごと | 起きること |
|---|---|
| 1回目にまちがえる | 自分が少しダメージを受ける。**ヒントが出て、もう一度同じ問題に挑戦できる** |
| やり直しで正解 | ダメージは半分入る(直せたことを評価する) |
| 2回目もまちがえる | 正解が表示される。次の問題へ |
| まちがえた問題 | 自動で復習モード(SRS)に登録される |
| HPが0になる | かいふく所に戻るだけ。持ち物もモンスターも失わない |

「1回まちがえたら終わり」にしないこと、「負けても失うものがない」ことを徹底している。
既存アプリが持っている丁寧な解説・ヒント資産を、バトル中にそのまま活かせる形にした。

バトルの長さは、野生3〜5問 / トレーナー戦は相手1体につき3問 / 単元マスター戦は
相手1体につき4問(3体)。野生1回が1〜2分で終わるので、集中が切れにくい。

## 4. 3Dの作り方

**3D空間 + 2Dビルボードスプライト**。ポケモンのDS/3DS作品と同じ手法。

- 地形・草むら・木・岩・水面・空・霧・ライティングは本物の3D(three.js)
- キャラクターとモンスターは、生成した2Dイラストをつねにカメラを向く板に貼る

無料で用意できるのは高品質な2Dイラストであって3Dモデルではない。
プリミティブを組んだ簡易3Dモデルにすると、かえって安っぽく見える。
この構成なら**絵の品質がそのまま画面の品質になる**。

### フィールドは町IDから決定的に生成する

地形の高さ・木や岩の配置・草むらの位置は、すべて町IDのハッシュを種にした
疑似乱数から作る(`components/adventure/field/terrain.ts`)。

- 端末が変わっても、再訪しても、フィールドが変わらない
- 座標をセーブしなくてよい
- 地形の高さをどこからでも同じ式で引ける(NPCを地面に立たせるのが楽)

### 軽さのための選択

- 実影は使わず、まるいブロブシャドウで表現(モバイルGPUの負荷が大きく違う)
- 同じ形の飾りはすべて `InstancedMesh` 1つにまとめる
- three.js を含むチャンクは動的インポート。練習モードしか使わない児童の
  初期読み込みを遅くしない(本体936KB / ぼうけん1,005KB に分割ずみ)
- フィールドの外側に大きな地面と遠景の丘を置き、「板の上を歩いている」ように
  見えないようにしている

## 5. 操作(iPad横持ち・小4想定)

- **左下のバーチャルパッド**: 押した場所が中心になる方式。パッドの真ん中を
  正確に押さなくても動かせる
- **画面タップ移動**: 行きたい場所をタップすると歩いていく。ゲームに慣れていない子が
  最初の一歩でつまずかないための保険
- **右下の大きな丸ボタン**: 近くにNPCがいるときだけ光り、話しかけられる
- バトル中の問題画面は、iPadを横に持つと**左に問題・右にキーパッド**の2カラムになる

## 6. 進行

- 14の町は**どこから回ってもよい**。教科書の進度に合わせたい場合は、先生が
  管理画面の「単元ロック」で閉じる(既存機能をそのまま流用)
- ロックされた町はマップで 🔒 表示になり、入れない
- 14個のバッジがそろうと**ナンバーリーグ**が開く(§13)
- 町ごとに、テキトウ団のサブイベントと、伝説の祠が現れる(§14・§15)

## 7. セーブとFirebase

`store/adventureStore.ts`。

- 平常時は **localStorage のみ**。Firebase未設定でも全機能が動く
- Firebase を設定してログインしている場合だけ、町の移動時とバトル終了後に
  `adventures/{uid}` へ `setDoc(merge)` を1回
- 端末をまたぐときは `updatedAt` が新しい方を採用するので、進行が巻きもどらない

フィールドを歩くたびに書き込むようなことはしていない(無料枠を使い切らないため)。

## 8. イラストの作り方

`scripts/` に生成パイプラインがある。詳しい手順は README を参照。

- **Pollinations.ai**(無料・APIキー不要)で1枚ずつ生成
- 背景は**必ずクロマグリーン**を指定させ、その色からの塗りつぶしで抜く
- 背景が緑でなければ「モデルが指示を無視した」と判断して**生成し直す**

最後の点は重要で、参照リポジトリ battlemath04catwars では背景を白にしていたため、
白い体のキャラが背景ごと溶ける不具合が起きていた。本作は
「背景色を検証してから抜く」ことでこれを構造的に防いでいる。
`scripts/check-sprites.mjs` が 200枚以上を機械的に検査して、抜け残り・抜きすぎを拾う。

### 画風

難易度が上がるほど、かわいい方から かっこいい方へ寄せている。

| 難易度 | グレード | 見た目 |
|---|---|---|
| 1〜2 | `baby` | まるっこくてやわらかい、パステル。武器も装備もなし |
| 3 | `brave` | 小さなマフラーやマントを着けた、元気な冒険者風 |
| 4 | `knight` | 簡素な鎧とマント。かっこいいが、こわくはしない |
| 5・ボス | `dragon` | まるい翼と短いしっぽを持つ、ちびドラゴン |

全生成で共通のスタイル文(フラットな2Dベクター / サンリオ風 / 大きな丸い目 /
グラデーション・毛並み・写実の排除)を共有して、画風のブレを抑えている。
グロテスクな表現・写実的すぎる描写は、ネガティブプロンプトで明示的に除外している。

## 10. ジム(単元マスター)への挑戦条件

いきなり道場へ突撃できると、その単元をほとんど解かないままマスター戦に入って
連敗する。町ごとに3つの条件を置き、満たすまで受けてくれないようにしている
(`data/adventure/gymRequirements.ts`)。

1. その町のトレーナー2人に勝つ
2. その単元のモンスターを N 体つかまえる(サブトピック数の約1/4、2〜6体)
3. その単元の問題に M 問正解する(サブトピック数の約1.5倍、6〜30問)

**3の正解数は学習記録(`learningLogService`)の単元別集計をそのまま見る**ので、
練習モードでその単元をやりこんだ子は、バトルをしなくても条件を満たせる。
学習の実績とゲームの進行を別々にしないための設計。

条件はHUDに常時、進捗バーで出している。未達のままマスターに話しかけると、
「何が足りないか」を1行ずつ教えてくれる。

根拠はマスタリー・ラーニング(到達基準を満たしてから次へ進む)のメタ分析
(Guskey & Gates 1986; Kulik et al. 1990 — エビデンスレベル1a)。

## 11. ステータスと称号

`data/adventure/ranks.ts` に、称号27種とトレーナーランク10段階を定義している。
判定はセーブと学習記録から**毎回計算するだけ**なので、条件をあとから変えても
過去のプレイにさかのぼって反映される(別に集計を持たない)。

- 称号の指標: つかまえた数 / 出会った数 / バッジ / 撃破数 / 正解数 / 最高レベル /
  訪れた町 / リーグ進行
- 獲得したら画面上部に通知を出す
- トレーナーカード画面で、ステータス一覧と「もうすこしで もらえる称号」を見せる

「あと少しで届く」を見せているのは、ゴール勾配(目標に近づくほど努力が増す。
Kivetz et al. 2006 — エビデンスレベル2)を意図したもの。

## 12. 進化 ― 熟達したときだけ、すがたが変わる

`data/adventure/evolutions.ts`。151項目のうち **44項目だけ**に進化を置いている。

### なぜ全部に付けないか

進化は「ここまで来た」という強い合図なので、どこにでもあると意味が薄れる。
そこで、**進化した価値がある項目**に絞った。選定の観点は3つで、各定義に
`reason` として残してある。

| reason | 意味 | 例 |
|---|---|---|
| `中核` | その単元の考え方そのもの | わり算の筆算・約分・小数のかけ算 |
| `土台` | あとの学年で必ず使う | 分数の意味・角の大きさ・面積の公式 |
| `つまずき` | 全国調査などで正答率が低い | 帯分数と仮分数・0を含むわり算・複合図形の面積 |

### 条件

レベルではなく、**その項目を5問れんぞくで正解できるようになったとき**に進化する
(`learningLogService` の `perfectStreak >= 5` = 熟達判定。既存の練習モードの
記録をそのまま使うので、練習モードでやりこんだ子はバトルに入った時点で進化する)。

レベルではなく理解度を条件にしたのは、マスタリー・ラーニング
(Guskey & Gates 1986; Kulik et al. 1990 — エビデンスレベル1a)と、
ごほうびを「行動量」ではなく「達成」に結びつけるため
(Deci, Koestner & Ryan 1999 — エビデンスレベル1a。作業量に報酬を出すと
内発的動機が下がる)。

図鑑では進化先が「？？？」で隠れており、条件の文だけ先に読める。

## 13. ナンバーリーグ ― さいごの回廊

`data/adventure/league.ts` と `components/adventure/field/League.tsx`。

14個のバッジがそろうと、マップから **専用の3Dフィールド**へ入れる。
ふだんの町が「四角い野原」なのに対し、ここだけは細長い屋内の一本道にしてある。

- 長さ156・幅18の回廊に、26おきに5つの間がならぶ
- 手前から 四天王4人 → いちばん奥がチャンピオンの間
- 勝つと、その相手の間の**かがり火がともり、奥の扉が開く**
- まだ開いていない扉より先へは歩けない(しきいが赤く光る)

「どこまで来たか」を、地図ではなく**歩いた距離と灯りの数**で分かるようにしている。

### 負けたときは進行を戻さない

本家は途中で負けると最初からだが、本作では**倒した四天王はそのまま**にしている。
小4にとって「30分やり直し」は再挑戦をやめる理由になり、
到達基準を満たすまで何度でも試せるというマスタリー・ラーニングの前提とも
矛盾するため。負けても扉は閉じない。

チャンピオンに勝ったあとも、チャンピオンはその場に立ち続けるので何度でも挑める。

## 14. 伝説・幻 ― 単元を総括する1体

`data/adventure/legends.ts`。**伝説7体**(タイプごとに1体)と**幻2体**。
それぞれ1体しかいない。

- 町に**祠**が建っており、近づいて調べると**伝承**が読める(条件を満たす前でも読める)
- 条件を満たすと祠のしるしが光り、光の柱が立つ。調べると出現し、勝てば必ず仲間になる
- 見た目は他のモンスターと**意図的に別系統**にしてある(かわいくしない)。
  `LEGEND_STYLE` は「重厚・威圧的・神話的な獣」で、`CREATURE_STYLE` の
  `cute / chibi / round` を打ち消している

### 出現条件

| | 条件 |
|---|---|
| 伝説(7体) | そのタイプの全単元で ①バッジを取る ②図鑑を8割うめる ③半分の項目で熟達する |
| ゼロディア | モンスターを100しゅるいつかまえる |
| ナンバリオン | チャンピオン + 14バッジ + 伝説7体すべて |

条件はどれも「その単元を本当にやりこんだか」だけを見ている。
レベル上げや周回では届かない。

### 目について

**すべてのモンスターは目が2つ**。生成プロンプトで `EXACTLY TWO EYES and no more`
を指定し、`no third eye / no extra eyes / no compound eyes / no asymmetric eyes` を
ネガティブに入れている。`scripts/check-sprites.mjs` では目の数までは判定できないので、
`scripts/contact-sheet.mjs` で一覧シートを作り、目視で確認している。

## 15. テキトウ団 ― 「だいたい合ってる」という敵

`data/adventure/team.ts`。名前のとおり、**答えをきちんと出さずに済ませようとする**
集団。「およそでいい」「めんどうだから四捨五入」と言い、算数の"だいたい"を
悪用しようとする。

5つの章が、バッジの数に応じて町に現れる。

| 章 | バッジ | 町 | 相手 |
|---|---|---|---|
| 1 | 1 | ケタバ村 | したっぱ |
| 2 | 3 | イシキリ谷 | ザツ |
| 3 | 5 | シズク湖 | オオザッパ |
| 4 | 8 | キリノ森 | アバウト |
| 5 | 11 | トキノ塔 | ザツ |
| アジト | 14(+5章クリア) | ハコニワ砂漠 | 幹部3人 → ボス マルメ |

ボスのマルメは「まるめる(四捨五入)」から来ている。倒したあと、
**がい数そのものは悪ではない**という話で終わる ―― 目的に合わせて
正確さと概算を使い分けるのが算数だ、という着地にしてある。

## 16. これから足すとしたら

追加要素の検討とエビデンス評定は **[docs/GAME_ELEMENTS_PROPOSAL.md](GAME_ELEMENTS_PROPOSAL.md)**
にまとめてある。§12〜15 で実装ずみのぶんを除いた、優先度の高い順:

1. **わすれかけ表示**(SRSの期限が来たモンスターを「ねむそう」にする)
2. **タマゴ = 分散練習**(異なる日に解かないと孵らない)
3. ライバルとの再戦イベント(`RIVALS` は定義ずみ)
4. 四天王との再戦(レベルを上げた手持ちで挑む)
5. 町ごとのBGM(現在は無音。Web Audio API での合成を想定)
