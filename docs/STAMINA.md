## スタミナ（学級ポータルの一部として動く から移した）

- **スタミナの たまり方（2026-10-25〜、サーバの `_sanmon_stamina`。SQL は `supabase-sql/2026-10-25-sanmon-stamina.sql`）**：
  単元アプリの正解1問 +1（ペア 0.5）。**1つの項目で1日5まで・もう熟達した項目（5問れんぞく正解のあと）は半分。1日の上限（前は30）はなし**。
  がんばりボーナス：実力の階段の新しい段 +3・はじめての熟達 +2（本番テストは下の「点数ぶん」に変えた）。ためられるのは100まで。前の日までは前のきまりのまま。
  **たまる・使うは時刻の順に数える**（2026-11-09 バグ直し。`supabase-sql/2026-11-09-sanmon-stamina-chronological.sql`）：前は1日ぶんまとめて「足して100で切る→その日に使った分を引く」だったので、使いきったあとに解いたぶんが消えていた。
  **町のスタミナ（2026-11-09 13:39〜 先生と決めた。SQL は `supabase-sql/2026-11-09-sanmon-town-stamina.sql`、サーバの `_sanmon_pools`）**：単元アプリの正解でたまる分は、その単元の町の「町のスタミナ」（町ごとに50まで）。
  がんばりボーナスは「共通スタミナ」（100まで。切りかえ前にたまっていた分も共通）。ぼうけんのバトルは 町 → 共通 の順に使う（`AdventureMode` の `startBattle` が reason に「@町の key」を付ける。key は kit の `sanmonTownKeyOf(town.unit)`）。
  スピード・モンスター対戦・クラス対戦は共通だけ（アプリの無い町は 2026-11-11 から町のスタミナあり。下に書いた）。わり算の筆算は 筆算の項目（hissan-?-1／?-2・?-3）で ÷1けた・÷2けたに分け、ほかの項目は2つの町の共有。小数は アプリの項目のまとまりで しくみ／かけ算わり算に分ける（表 `sanmon_skill_town`）。
  **本番テストは点数ぶん**（2026-11-10 17:30〜 先生と決めた。SQL は `supabase-sql/2026-11-10-sanmon-test-points.sql`）：点数の割合×10（切り捨て）を、そのテストの単元の**町のスタミナ**へ（町の無いテスト・SANMON の本番テストは共通）。
  受けるたびにもらえる・同じテストは1日3回まで・DUO は0。簡単なテストばかり受けても、その町にしかたまらないようにするため。前の「8割合格 +5（共通）」は切りかえ前の分だけ数える。
  **スタミナの釣り合い**（2026-11-10 23:15〜 先生と決めた。SQL は `supabase-sql/2026-11-10-sanmon-balance.sql`）：1分あたりのスタミナを、練習・本番テスト・実力の階段で だいたい そろえる（どれも1分に2〜3。マッチング法則）。
  **小4算数のアプリ（apps の grade=4・subject='算数'）と SANMON だけ**（国語・英語・5〜6年は 正解・熟達・階段とも0）。
  本番テストは テストの大きさに合わせる：ぜんぶ（150点）で満点の割合×20、表だけ・裏だけは その分（`_sanmon_test_full`。倍の見方は100点で1枚）。同じテスト（表・裏・ぜんぶは別）の その日1回目は満額・2〜3回目は半分・4回目から0。
  SANMON の本番テストも テストの名前の番号で町を決める（`_sanmon_test_pool`：3→わり算・4→がい数・5→小数・6→分数。大きい数・折れ線・まとめは共通で その日1回目だけ）。
  実力の階段（極限）は その回に のぼった段×3 を その単元の町へ（アプリごとに その日1回目は満額・2回目は半分）。はじめての段 +3・はじめての熟達 +2 は共通のまま。
  **アプリの無い町（大きい数・折れ線グラフ・角）にも町のスタミナ**（2026-11-11 10:50〜 先生と決めた。SQL は `supabase-sql/2026-11-11-sanmon-noapp-towns.sql`）：SANMON の れんしゅう・ふくしゅう の正解（learning_event の module_id＝町の key、label が「れんしゅう：」「ふくしゅう：」）を その町へ（アプリと同じ数え方）。
  バトル・デュエルの中の答えは数えない（バトルでスタミナが戻らないように）。SANMON の本番テスト「1. 大きい数」「2. 折れ線グラフ」も その町へ。画面は「サーバが towns を返す町」に町のスタミナを出す（`key in stamina.towns`）。
  **バトル1回のスタミナは町の達成度で安くなる**（2026-11-11 先生と決めた。SQL は `supabase-sql/2026-11-11-sanmon-town-cost.sql`）：達成度＝その町の単元の練習の項目のうち熟達（5れんぞくノーミス）した割合。100％→2・75％以上→3・50％以上→4・それより下→5。アプリの無い町・スピード・対戦は5。
  決めるのはサーバ（`sanmon_spend` が `_sanmon_town_cost` で計算。送られた数は使わない）。画面の「1回 n」は `utils/townCost.ts`（同じ項目＝kit のカタログ・同じ熟達）。
  **アプリの無い町（大きい数・折れ線グラフ・角）は 1回 3**（2026-11-12 先生と決めた。前は 5。SQL は `supabase-sql/2026-11-12-sanmon-noapp-town-cost.sql`、画面は `utils/townCost.ts` の `NO_APP_TOWN_COST`）。
  **kit のカタログ（項目）を変えたら、サーバの表 `sanmon_town_skill` を作り直す**（`node scripts/export-town-skills.mjs` の行で）。
  わり算の筆算の2つの町（÷1けた・÷2けた）は、練習の条件も達成度も**同じ32項目**で数える（同じ条件で いっしょに開く）。筆算シミュレーターの5項目（hissan-2-1〜3-3）は 2026-11-11 に足した（kit 0.34.1。前はカタログに無く、筆算そのものが数えられていなかった。SQL は `supabase-sql/2026-11-11-sanmon-hissan-core-skills.sql`）。
  画面は**文字で**出す（2026-11-10）：ぼうけんの左上に「スタミナ／この町 n/50 ・ 共通 n/100／▶ バトル あと n回（1回 5）」、マップの町ごとに「町のスタミナ n/50」、
  メニューの帯に「スタミナ 共通 n/100」と「共通だけで バトル あと n回」、ひらくと町ごと（`PortalStatusBar`）。
  かんたんな項目の周回では たまりにくく、いろいろな項目・苦手・テスト・階段で よく たまる。kit の `SANMON_RULES.dailyCap` は もう使っていない（子ども用ハブの説明が「30まで」なら 全体セッションで直す）。
