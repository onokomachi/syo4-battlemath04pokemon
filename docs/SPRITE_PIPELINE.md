# スプライト生成 — 何を学んだかの記録

モンスター214体+NPC+地形の絵をどう用意しているか。
**プロンプトを書きかえる前にここを読むこと。** 読まずに触ると、
輪郭が食われた絵を量産して無料枠を溶かす(実際に3日連続でやった)。

各スクリプトの中にも判断の理由をコメントで書いてある。ここは全体像と、
コードコメントに書ききれない「運用」の話。

---

## 1. 生成の道具

**Cloudflare Workers AI の `@cf/black-forest-labs/flux-1-schnell`。**

- **Pollinations からの乗りかえ理由**: (プロンプト, seed) ではなく **seed だけで
  キャッシュ**していて、プロンプトを直しても同じ絵が返ってきた。
  設計をやり直すには、直した文がそのまま効く必要がある。
- **SDXL を選ばなかった理由**: 「背景をクロマグリーンで塗れ」と何度書いても
  灰色のスタジオ背景を描き、切り抜きができなかった。flux は指定どおり
  ベタ塗りの背景を出す。
- **無料枠は 1日 10,000 neurons。** 一度に全部は作れないので、
  `scripts/regen-pending.txt` に「まだ作れていないもの」を書いておき、
  枠が回復した日にそこから続ける、という進め方をしていた。

```bash
node scripts/build-sprite-manifest.mjs                    # ジョブ一覧を作る
node scripts/gen-cf-sprites.mjs                           # 生成(既存はスキップ)
node scripts/gen-cf-sprites.mjs --force --only monsters/mon-001
node scripts/check-sprites.mjs --bad                      # 機械で検査
```

認証情報は環境変数か `.env.local` からしか読まない。**ファイルに書かない。**

## 2. プロンプトで効いたこと

### 並び順が結果を決める

flux は長いプロンプトの後半を落とす。1500字書いていたときは末尾の motif と
色指定がまるごと無視され、**どのモンスターも同じ「丸っこい白い動物」**になった。

→ **① 背景 → ② 何を描くか(motif) → ③ 画風 → ④ 除外** の順に固定し、
全体を700字前後に切りつめた。**②を前に出すのが要点。**

### 否定形は効かない。むしろ逆に効く

flux は否定を解さない。`no third eye` と書くと third eye が効いて複眼が出る。
伝説の生成で `no human` と書いたら人が出た。
→ **あってほしい状態だけを言いきる。** `exactly two eyes, one left one right, …`

### 「グリーンスクリーン」と言いきる

「緑の背景」程度では、「荘厳」「壮大」と指定した伝説の絵で
モデルが勝手に暗い情景を描き、背景が緑でなくなった。
`PURE GREEN SCREEN` / `chroma key studio shot` と強く言う。

### 物語的な言い回しを書かない

「嵐を呼ぶ」「古代の神殿を守る」のように書くと、
**モデルがその情景を背景に描いてしまい**、クロマキーが抜けなくなる。
motif は「体の見た目」だけを書く。

## 3. いちばんの失敗 —「輪郭が食われている」

検査で 15体が3日連続で落ちた。原因は**モチーフの側**にあった。

背景除去は「背景色につながった画素を消す」ので、
**体から離れたパーツは背景と地続きになり、まるごと消える。**

落ちたモチーフの共通点:

| 危ない書き方 | どうなるか | 直し方 |
|---|---|---|
| 体から離れて浮く飾り | 飾りが消え、周りも欠ける | 体にくっついた飾りにする |
| まき散らされた粒・火花 | 粒のあいだの背景とつながって食われる | 体の表面の模様にする |
| 双頭・分かれた形 | あいだの空間が食われる | 一つの頭にする |
| 細長い胴・長い尾が伸びる | 細い部分が途中で切れる | 体に巻きつける・太くする |

→ 15体すべてのモチーフを「体にくっついた表現」に書きかえたら通った。
**背景を抜くことを前提に、モチーフの側を設計する。**

---

## 4. 背景の色は1体ごとに選ぶ

**体の色が緑に寄っているモンスターは、緑背景だと体まで抜ける。**
だから `scripts/spriteJobs.ts` で 1体ごとに green / magenta を選べるようにしてある。

- 体色が緑寄り(`isGreenish`)→ **マゼンタ背景**
- 伝説は**つねにマゼンタ**(金や深い青緑をまとうため)
- 個別の例外は `MONSTER_CHROMA_OVERRIDE` に書く
  (例: カクセイバーは金の光が緑がかって出るのでマゼンタ)

---

## 5. 外から用意した絵を取りこむ

生成AIに任せきれない絵(伝説など)は、外で作って取りこむ。

```bash
node scripts/import-sprite.mjs <入力画像> <出力名> [--large]
```

- 背景が **緑 / マゼンタ / 市松模様** のどれかを自動判定して抜く
- 256×256 の透過PNGにそろえる
- `--large` はキャラを枠いっぱいに大きく置く(**伝説・幻に使う**)
- 取りこんだものは `scripts/manual-sprites.json` に自動登録され、
  **以後どんな `--force` でも生成に上書きされない**(これが無いと人の絵が消える)

### 背景判定は「最頻値」で見る

当初は端の色の**中央値**で背景色を判定していたが、
キャラが画像の端まではみ出している絵で誤判定した。
**端の色でいちばん多いもの(最頻値)**に変えたら安定した。

## 6. 絵を人から受けとる手順(実際に53体でやった)

チャットに貼られた画像は、この実行環境では**ファイルとして読めない**。
そこで次の手順にした。**これが確実だった。**

1. ブランチに `incoming-sprites/` を作る
2. 生成した画像を**モンスター名のローマ字**にリネームして置いてもらう
   (`naosun.PNG` = ナオスン、`obikarionn.PNG` = オビカリオン)
3. こちらでファイル名とゲーム内データを突き合わせ、
   **対応表が全件一意になることを機械で確認してから**取りこむ
4. 取りこみ後 `incoming-sprites/` を消す

ローマ字が似ているもの(`obikari` / `obikarin` / `obikarionn` = 基本形 / 進化前 / 進化後)
があるので、**数だけ合わせず、名前・進化関係と突き合わせて検証する。**
